# バス接近AR

公共交通オープンデータチャレンジ2026 向け。Even G2 で、選んだバス停・乗り場の次の便
（系統・行先・カウントダウン）と、接近してくるバスの位置を出す。iOS 版（AR）はあとで。

**iOS 版（ARKit）は [ios/](ios/README.md)。** 同じ中継を使い、カメラ越しにバスの実際の方向を出す。

**対応範囲: 川崎市バス 477 停留所・川崎鶴見臨港バス 394 停留所（全停留所）。両社が止まるバス停は
1 つにまとめ（87 か所, 871 停留所 → 784 バス停）、両社の便を 1 つの発車案内に混ぜる。**
アプリに同梱するのは停留所の索引（123KB）だけで、時刻表は選んだ停留所の「その日のぶん」を
中継から取る（全停留所で 263MB、1 日ぶんに切り出して gzip すると最大 20KB 程度）。

企画は Notion の
[公共交通オープンデータチャレンジ2026 — 川崎バス接近AR／Even 構想メモ](https://app.notion.com/p/3e71b0c05d9b81c5a99ad02ff3922106)。
G2 の画面構成・送信・入力の扱いは `~/Developer/G2SkyView` から、選択の記憶は
`~/Developer/Tokyojihatsu` から持ってきた（元は変更していない）。

### 上の帯: 道路モデル（模式図）

乗り場で道路側を向いた向きを 0° として、**右へ 60° 向いている**ことを想定する。
その視線の先にまっすぐな道路が奥へ延びていると仮定し（消失点 = 右 60°・地平線上）、
バスを**経路に沿った乗り場までの残り距離**で道路上に置く。遠いほど消失点に近く小さく、
近づくと左下の「乗り場」へ降りてくる。距離は対数で写す（20m〜4km を 1 本の道路に収める）。

**実際の方位ではない。** 大師橋駅前は駅前ロータリー（一方通行のループ）で、乗り場 1〜3 で
道路を向くと南、右 60° は西南西になり、そこに見えるのはロータリーの U ターン部分だけ。
実際のバスは殿町方面（東北東）→ 南東の入口 → ロータリー内の順に来る（2026-09-27 OSM で確認）。
実方位で描くと視野に入るのは最後の数十 m だけなので、道路モデルにした（2026-09-27 判断）。

メニュー: 乗り場・バス停を選び直す ・ 向きを右 60° に戻す ・ 回転の刻み 5/2/10° ・ 画角 30/45/20° ・

前回の停留所・乗り場・視線の角度を覚えていて、次は接近ビューから始まる。

## 時刻の根拠

| 表示 | 根拠 |
|---|---|
| `乗り場で待機中` / `接近中` | 発車便そのものが RT に出ている（車両が前の便を終えたあと） |
| `…停前 推定` | 同じ乗り場・系統へ**着く便の車両がそのまま折り返す**と仮定して結びつけた |
| `車両未確認 時刻表の予定` | 時刻表だけ |

遅れの見込み（`あと18分(+9分)`）は、折り返してくる車両の到着見込み + 1 分より前には出ない、として出す。

## データ監査（Phase 0, 2026-09-27）

| 項目 | 結果 |
|---|---|
| 大師橋駅前に停まる事業者 | **臨港バスのみ**（川崎市バスは無し） |
| 停留所の性格 | **始発・終点**。どの便もここで終わるか、ここから出る |
| 乗り場 | 1（大01 浮島BT）・2（大02 ENEOS浮島前）・3（大109 天空橋駅 / 空84 羽田空港）・5（大05 塩浜営業所 / 川03 川崎駅前）。**座標はほぼ同じ点**（差 10m 以内）なので `platform_code` で区別する |
| shapes.txt | 川崎市バスは無し、臨港バスはヘッダーだけ → 道路形状は停留所を結んだ折れ線で近似 |
| 祝日 | `calendar_dates.txt` で平日ダイヤを外し日曜ダイヤを足している → 祝日計算は不要 |
| RT の URL | vehicle / trip_update / alert の 3 つが**同じ統合フィード**を返す（車両 75 + 便 75） |
| trip_id の照合 | 150/150 が静的 GTFS と一致 |
| 車両位置の鮮度 | 取得時点で 20〜130 秒前、中央値 50 秒前後 |
| 始発便 | **発車前から RT に出る**（乗り場で STOPPED_AT・停車順 1）。到着便と発車便は車両 ID でつながる |
| 終点の到着予測 | 遅れが 0 に戻っていることが多い → 途中の遅れを足した値と大きい方をとる |

## 使い方（開発）

```bash
npm install
cp .env.example .env    # ODPT_TOKEN を書く（Tokyojihatsu と同じもの）
# 静的 GTFS を data/raw/ に取得・展開してから（URL は ckan.odpt.org の各データセット）
npm run build:all       # data/stops/<feed>/<id>.json（871 停留所）と data/stops/index.json を生成（約 5 秒）
npm test                # ネットワーク不要
npm run typecheck
npm run board -- --stop rinko:5010                      # 今の発車案内（RT 込み）
npm run board -- --stop kawasaki_city:94                # 川崎駅（市バス）
npm run board -- --at 2026-09-28T07:30 --platform 1     # 時刻を指定（時刻表のみ）
npm run rt:audit -- rinko --save                        # RT の監査・保存
```

ブラウザ・実機（QR サイドロード）:

```bash
npm run app:dev     # :5179。dev サーバーが ODPT の中継を兼ねる（/api/rt?feed=rinko）
npm run app:qr      # 実機に読ませる QR
```

ブラウザでは矢印キーでスワイプ、スペースでタップ、Backspace でダブルタップ。

## 中継（proxy/）

Lambda Function URL 1 本と非公開の S3 バケット（`KawasakiBusProxyStack`, 個人アカウント・東京リージョン）。
中身は `proxy/src/rt-proxy.ts` で、dev サーバーも同じ関数を通る（停留所データは S3 の代わりにローカルから読む）。

| 経路 | 返すもの |
|---|---|
| `/stop?key=rinko:5010` | 停留所の時刻表。**その日に走る便だけ**（前日の 24 時超え・翌日の早朝を含む）、gzip |
| `/rt?key=rinko:5010` | その停留所・その日の便に関係する車両位置・予測 |
| `/?feed=rinko` | 0.1.0（大師橋駅前だけのベータ）との互換 |

停留所データは S3 から読み、Lambda の中で 1 時間持つ（置き直しは 1 時間以内に効く）。

- **ODPT のトークン**は SSM の SecureString（Tokyojihatsu の `/tokyojihatsu/odpt-token` を共用）から
  実行時に読む。テンプレートにも `.ehpk` にも入らない（ビルド結果を検索して確認済み）。
- **素通しにしない**（基本ライセンス第 8 条 4(1)）。共有鍵（`X-Bus-Key`）の無いリクエストは 403、
  IP ごとに毎分 60 回まで、返すのは**収録している停留所に関係する便だけ**（臨港バス全体の 77 台 → 5 台前後）。
  共有鍵は `.ehpk` に入る値なので秘密ではない（Tokyojihatsu・G2 Sky View と同じ割り切り）。
- 上流はフィードごとに 15 秒キャッシュ。ログは 7 日で消える。

## 公開リポジトリに入れないもの

`data/stops/*.json`（時刻表の切り出し）は**コミットしない**。基本ライセンス第 8 条 4(1) が
「第三者が再利用可能な状態での公開・再配布」を禁じているため。`npm run build:stop` で生成する
（Tokyojihatsu が公開しているのは駅と時刻表 ID の対応表だけで、時刻表そのものは入れていない）。

```
src/core/
├─ stopdata.ts   1 停留所ぶんの静的データの型
├─ service.ts    運行日（calendar + calendar_dates）と次の発車
├─ realtime.ts   RT を JSON にした形（復号は中継側）

├─ approach.ts   道路モデルの表示リスト（右 60°・消失点・奥行き）
├─ render.ts     ビットマップに描く（G2 Sky View の方針: 塗らずに線）
├─ stops.ts      近いバス停・乗り場の選択肢
└─ bitmap / geodesy / textfit / orientation   G2 Sky View から複製

app/src/               G2 プラグイン（main / display / events / text / selection）
scripts/build-stop.ts  GTFS-JP → data/stops/<name>.json
scripts/board-cli.ts   発車案内の CLI
scripts/rt-audit.ts    RT の監査
```

## 両社のバス停をまとめる（src/core/grouping.ts, src/core/merge.ts）

| 規則 | 例 |
|---|---|
| 名前の末尾の「前」を外して一致し、150m 以内 | 川崎駅（市）＝川崎駅前（臨港）55m、ほか 85 か所 |
| 片方の名前がもう片方の頭に含まれ、60m 以内 | 観音二丁目川崎大師口（市）＝観音二丁目（臨港）12m |
| 同名でも 150m を超える → まとめない | 神明社前 8km、山崎 5km、桜本 700m、下平間 220m（系統が重ならない） |
| 名前が全く違う → まとめない | 昭和駅前 / レゾナック前 25m（道路の反対側かもしれない） |

同じ事業者の停留所どうしはまとめない。他社とは最も近い 1 つとだけ組む。代表名は便の多い方。
まとめたバス停の鍵はメンバーを `+` でつなぐ（`kawasaki_city:94+rinko:10`）。中継が各社の時刻表・
リアルタイムを取ってまとめ、便・運行・乗り場・車両の ID に `<feed>/` を付けて名前空間を分ける
（両社に同じ車両番号があっても取り違えない）。乗り場は「臨港 1番」「市バス 川04 …」と事業者を添えて出し、
複数の乗り場を見ているときは文字欄の 1 行目に乗り場を出す（「▶臨港1番 川21 水江町 08:32発」）。

## 全展開で見つかった課題（2026-09-27）

- **両社で停留所名が違う。** 川崎駅東口は臨港「川崎駅前」（乗り場 16）と市バス「川崎駅」（9）。
  同名の停留所だけをまとめると、一番大事な駅を取りこぼす → 下の「両社のバス停をまとめる」。
- **市バスは platform_code が空。** stop_id の末尾（`94_11` など）は乗り場番号でも系統番号でもない。
  乗り場は「系統・行先」で選ばせている。座標も 10〜80m ずれるので、座標だけで両社の乗り場を対応づけられない。
- **降車場と乗り場が別の停留所がある**（市バス川崎駅の `94_2`）。折り返しの推定は、同じ乗り場が無ければ
  同じ停留所の別の乗り場に着く同じ系統の車両で結ぶ。止まっているときは「到着済み」と出す。
- **市バスのフィードに古い位置が混ざる**（最大 8 時間前）。5 分より古い位置は使わない。
- 共同運行らしい系統がある（市バスの行先「川崎駅（臨港バス）」）。
- **経路の使い回しで停車順がずれていた**（修正済み）。停留所の並びが同じでも便によって停車順の番号が違う。
  経路は停車順も含めて同じときだけ共有する。症状は「残 7.0km・0 停前」のような矛盾。
- **同じ停留所に 2 回着く便がある**（循環系統。さいか屋前で 769 便など 12 停留所）。車両より先の到着で結ぶ。

## 他社のデータ（2026-09-27 調査）

川崎市内を走る他の事業者で、ODPT にあるもの。停留所の数は国土数値情報の区界で数えた川崎市内のもの
（「新しい場所」は市バス・臨港の停留所から 150m 以上離れていて、足すと新しく引けるようになる場所）。

| 事業者 | 形式 | ライセンス | リアルタイム | 川崎市内 | 新しい場所 | 載せやすさ |
|---|---|---|---|---|---|---|
| 小田急バス | GTFS（calendar_dates だけ） | 基本 | **なし** | 172（麻生 103・多摩 50・宮前 19） | 110（麻生 77・多摩 32） | 形式はそのまま載る。ただし**版が期間限定で空白がある** |
| 東急バス | ODPT JSON（BusTimetable 等） | 基本 | **なし**（odpt:Bus は 0 件） | 266（宮前 95・高津 60・中原 46 …） | 83（宮前 36・高津 20 …） | JSON → StopData の変換が要る。平日/土/休の曜日種別なので祝日判定も要る（Tokyojihatsu に実装あり） |
| 横浜市営バス | GTFS + GTFS-RT、shapes.txt あり | 基本 | あり | 4（幸区だけ） | 0 | 載せるのは簡単だが、川崎ではほぼ効かない |
| 神奈川中央交通 | ODPT JSON | チャレンジ限定 | なし（odpt:Bus 0 件） | 不明 | 不明 | **標柱の座標が全部 null**。近くのバス停を探せない |
| 京急バス | — | — | — | — | — | ODPT にデータなし |

見つかったこと:
- **小田急バスの GTFS は 1〜2 か月ごとの期間限定の版**で、間に空白がある: 0601 版（6/1–6/30）、0716 版（7/16–7/31）、
  0924 版（10/1–11/30）。7/1–7/15 と 8/1–9/30 はどの版にも無く、**今日（9/27）は小田急バスの時刻表が引けない**。
  載せるなら「日付で版を選ぶ」「空白の日は時刻表なしと出す」が要る。calendar.txt が無いので loadFeed も直す。
- **東急バスの BusTimetable は API の 1 回 1000 件の上限に当たる**（2MB で 1000 件ちょうど）。全件を取るには
  系統ごとに分けて取るか、ダンプを使う必要がある。
- 他社はどれも**リアルタイムが無い**ので、足しても時刻表のカウントダウンだけで、接近ビューにバスは出ない。
  川崎でバスの位置まで出せるのは、今のところ市バスと臨港バスだけ。
